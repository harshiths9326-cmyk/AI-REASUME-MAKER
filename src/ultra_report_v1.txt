# AI RESUME MAKER - COMPREHENSIVE INTERNSHIP REPORT

## 1. FRONT MATTER

### 1.1 ABSTRACT
The AI Resume Maker is an intelligent, web-based application designed to automate and professionalize the process of resume creation. Developing a high-quality resume is often a hurdle for students and freshers due to formatting complexities and a lack of understanding of industry standards. This project addresses these challenges by providing a user-friendly platform built on Next.js, TypeScript, and Supabase. The system features dynamic template switching, real-time preview, secure cloud storage, and high-fidelity PDF generation. By leveraging a modular architecture and cloud-native services, the application ensures scalability, performance, and accessibility across all devices. This report documents the end-to-end development life cycle, from requirement analysis and system design to implementation and deployment.

### 1.2 PREFACE
This project was undertaken during my internship at NH Internships. The goal was to build a real-world productivity tool that solves a genuine problem while adhering to professional software engineering standards.

# 2. INTRODUCTION & BACKGROUND

## 2.1 OVERVIEW
In the modern job market, a resume is more than just a list of qualifications; it is a marketing tool that represents a candidate's professional identity. However, the manual creation of resumes remains a tedious task for many. Users often struggle with word processors, alignment issues, and selecting appropriate layouts. The AI Resume Maker aims to solve these pain points by offering a structured, automated approach to resume building.

[IMAGE: landing_page_screenshot_1778698938455.png | Figure 1: The AI Resume Maker Landing Page with Cyberpunk Aesthetics]

## 2.2 PROBLEM DEFINITION
Traditional methods of resume creation involve using desktop word processors like Microsoft Word. These tools, while powerful, require significant manual effort for formatting. Beginners often face:
- Inconsistent spacing and alignment.
- Difficulty in organizing technical projects and certifications.
- Lack of professional-grade templates.
- No central place to store and update multiple versions of a resume.

## 2.3 PROPOSED SYSTEM
The proposed system is a full-stack Next.js application that decouples content from presentation. Users enter their data once, and the system handles the rendering into multiple professional styles.

# 3. LITERATURE SURVEY

## 3.1 NEXT.JS VS. TRADITIONAL REACT
React.js has revolutionized web development by introducing a component-based architecture. Next.js, built on top of React, adds critical features like Server-Side Rendering (SSR) and Static Site Generation (SSG). For a resume builder, Next.js is superior because:
- Faster initial page loads.
- Better SEO for public profiles.
- Built-in routing and API handling.

## 3.2 SUPABASE: THE OPEN SOURCE FIREBASE ALTERNATIVE
Traditionally, developers had to manage their own servers and databases. Modern BaaS (Backend as a Service) platforms like Supabase provide:
- Real-time PostgreSQL database.
- Secure Authentication with JWT.
- Row-Level Security (RLS) for data privacy.

# 4. SYSTEM REQUIREMENT ANALYSIS

## 4.1 FUNCTIONAL REQUIREMENTS
1. User Authentication: Secure login/signup.
2. Data Persistence: Resumes must be saved and retrievable.
3. Live Preview: Instant feedback on data entry.

5. PDF Export: High-fidelity generation.

## 4.2 NON-FUNCTIONAL REQUIREMENTS
- Performance: Preview updates in < 100ms.
- Scalability: Support for thousands of concurrent users.
- Security: End-to-end encryption for user data.

1. **Presentation Layer**: Next.js (React) + Tailwind CSS.

# 6. TECHNICAL IMPLEMENTATION

## 6.1 DATABASE SCHEMA
The database is structured to support relational data for complex resumes.

```sql
CREATE TABLE resumes (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id UUID REFERENCES auth.users(id),
  data JSONB NOT NULL,
  template_id TEXT DEFAULT 'modern',
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

# 10. SOFTWARE DEVELOPMENT LIFE CYCLE (SDLC)

## 10.1 PLANNING PHASE
Initial research involved identifying the most common pain points in resume building. We decided on a "Single Page Application" (SPA) approach to minimize page reloads and provide a snappy user experience.

## 10.2 ANALYSIS PHASE
We analyzed the requirements for ATS (Applicant Tracking System) compatibility. We learned that standard fonts (Arial, Helvetica) and clear section headers are critical.

## 10.3 DESIGN PHASE
Using Figma, we designed the cyberpunk landing page and the dual-pane builder interface. The goal was "Information at a Glance".

## 10.4 IMPLEMENTATION PHASE
This phase involved 8 weeks of coding, divided into sprints. We used GitHub for version control and Vercel for continuous deployment.

# 11. DATABASE ARCHITECTURE & SCALABILITY

## 11.1 THE CHOICE OF POSTGRESQL
PostgreSQL was chosen for its reliability and its support for JSONB data types. This allows us to store unstructured resume data while still maintaining the speed of a relational database.

## 11.2 ROW-LEVEL SECURITY (RLS)
Security is paramount. With Supabase RLS, we ensure that a user can only access their own resume records:
```sql
CREATE POLICY "Users can only see their own resumes" 
ON resumes FOR ALL
USING (auth.uid() = user_id);
```

# 12. REACT STATE MANAGEMENT

## 12.1 THE POWER OF USESTATE AND USEEFFECT
We avoided complex state libraries like Redux to keep the application lightweight. Instead, we used React's built-in `useState` for the resume data and `useEffect` for persistence.

```typescript
const [data, setData] = useState(initialData);

useEffect(() => {
  const saved = localStorage.getItem('resume_data');
  if (saved) setData(JSON.parse(saved));
}, []);

useEffect(() => {
  localStorage.setItem('resume_data', JSON.stringify(data));
}, [data]);
```

# 18. APPENDICES

## 18.1 FULL SOURCE CODE: MAIN LOGIC (app/builder/page.tsx)
```tsx
"use client"
import { useState, useEffect } from "react"
import { initialResumeData, ResumeData } from "@/lib/types"

function BuilderContent() {
    const [data, setData] = useState<ResumeData>(initialResumeData)
    useEffect(() => {
        const savedData = sessionStorage.getItem("resume_builder_data")
        if (savedData) setData(JSON.parse(savedData))
    }, [])

    const updateData = (newData: Partial<ResumeData>) => {
        setData((prev) => ({ ...prev, ...newData }))
    }

    return (
        <div className="grid grid-cols-1 lg:grid-cols-2 gap-6 h-full">
            <ResumeForm data={data} updateData={updateData} />
            <ResumePreview data={data} />
        </div>
    )
}
```
